# Native effect capsules

This tracked implementation starts from the validated standalone producer in
`benchmark-output/typed-effects-prototype-v1/native`. Its historical eleven-test
receipt remains qualified to that exact source/DTO generation. Current callable
v2 adaptation and the concrete pinned-provider adapter require fresh checks.

The producer reuses the native class parser, structural decoder and all-path
effect summaries. It retains known fields/calls after open operations, compares
every field/call/allocation PC before finite narrowing, and keeps unresolved
methods, initialization phases and VM/loading boundaries explicit.

Only the explicit instruction-local JVM contract can close selected local
channels. It is bound to a normally admitted declared runtime, producer and
captured contexts. The contract grants no runner isolation, whole-method
closure, source/native identity shortcut or selection authority. Synthetic
phase/adapter keys remain distinct from real JVM methods.

The provider module admits the exact compiler-context and native-map pins,
ordered physical entries and optional bootstrap inventory. The compiled-product
linker additionally requires the opaque retained-Zinc source/product proof.
No provider is selected by class name or matching class SHA alone.

`library_inventory::issue` separately issues provider-bound file trust for the
conditional application-impact diagnostic. It accepts an explicit archive SHA
policy and the normally admitted declared java.base; it never infers trust from
package names or archive paths. Each record binds the sealed fact snapshot,
compiler context, actual selected provider, ordered-prefix receipt and exact
class bytes. Source-owned files, captured application products, ambiguous or
opaque lookups and unmatched policy entries stay untrusted. Physical provenance
and resource failures are errors. The issuer changes no facts or strict native
recipes and grants no dispatch, callback, initialization or VM-effect closure.

The planner can convert `providers()` and `files()` to its independent numeric
DTOs and bind `identity()` as its source inventory identity. `file_proofs()` and
`denials()` provide bounded provenance and refusal diagnostics. A file with no
issued record remains an application/reference frontier; absence is never a
library-trust certificate. Compiler references with no file require a separate
exact compiler-to-native binding, rather than a package or spelling shortcut.
